# MP Control — продуктовая версия дашборда Mocheqi: решения и план

Итоги чата от 07.11.2026 (проект «Buisness»). Этот файл — для чата дашборда Mocheqi: прочитай его вместе с `docs/PASSPORT.md` репозитория mocheqi и продолжай по плану ниже.

## 1. Что уже сделано

- Создан закрытый репозиторий **nadegdakorneeva-coder/mp-control** (ветка main) — копия кода mocheqi на коммите `4418dcd`, рабочая папка на ПК **D:\MPControl**. Программу Mocheqi (D:\MP\dashboard, репозиторий mocheqi) не меняли.
- В mp-control (коммит `051273a`) разведены имена, чтобы обе программы работали на одном ПК одновременно:

| Что | Mocheqi | MP Control |
|---|---|---|
| Порт | 8765 | 8766 (виджет берёт порт из `config.ini`) |
| Cookie входа | `mp_session` | `mpc_session` — браузер не делит cookie по портам, иначе вход в одну программу выкидывал из другой |
| Задачи Windows | «MP Dashboard - …» | «MP Control - …» |
| Ярлык виджета / правило брандмауэра | «Mocheqi widget» / «MP Dashboard 8765» | «MP Control widget» / «MP Control 8766» |
| Название по умолчанию | Mocheqi | MP Control |
| Сервер Linux | `mocheqi`, `/opt/mocheqi` | `mpcontrol`, `/opt/mpcontrol`, репозиторий mp-control |

- В `docs/PASSPORT.md` mp-control — шапка и список «Что убрать для продукта» (что в коде осталось от Mocheqi).
- Осторожно: если в MP Control вписать ключи API Mocheqi, лимиты WB общие на токен — не запускать полные загрузки обеих программ одновременно.

## 2. Решения (согласованы с пользователем)

1. **Одна программа, без двойной работы.** Разработка продолжается в репозитории **mocheqi**, как сейчас. Копию в конце не делаем: после копии каждую правку пришлось бы делать дважды.
2. **Тумблер «Режим продукта»** в «Прочее → Настройки» (только админ). По умолчанию выключен — Mocheqi открывается как сейчас. Включил — появляются продуктовые разделы (можно проверить), выключил — снова скрыты, данные Mocheqi не меняются. В сборке для клиентов режим включён жёстко, без тумблера.
3. **Особенности Mocheqi → в настройки** (для Mocheqi там текущие значения, у нового клиента — пусто):
   - Google Таблица расходов: лист «Мосийчук М.В. 2026», колонки-счета (WB, Ozon, СБЕР, наличные Игорь/Наташа/Олег, Касса), правила типов операций, год 2026 (`app/gsheet.py`);
   - МРЦ из прайса MOCHEQI (`app/rrp_seed.json` грузится автоматически в пустую таблицу — у клиента не должно);
   - стартовые магазины «Mocheqi» / «Mocheqi_Ozon» (`app/db.py`), название, подсказка «страница бренда MOCHEQI» в `app.js`.
4. **Развод имён — в общем коде, а не правкой копии:** порт из `config.ini`, имя cookie, задачи Windows, ярлык и правило брандмауэра строятся от настроек (например, cookie `mp_session_<порт>`), так что для Mocheqi всё остаётся как есть. Правки из таблицы выше перенести в mocheqi в таком виде.
5. **Распространение — вариант «один общий сервер» (SaaS).** Клиент ничего не устанавливает и не получает файлов: регистрируется на сайте, платит подписку, вписывает свои ключи WB/Ozon и работает в браузере. Варианты «сервер на каждого клиента» и «файлы на ПК клиента с файлом лицензии» отклонены (второй — код на Python открытый, проверку лицензии легко убрать).
6. Судьба репозитория mp-control — решить позже: либо продуктовая сборка, которая получает изменения из mocheqi в одну сторону, либо не нужен, когда в mocheqi появится режим продукта.

## 3. Что нужно для общего сервера

**Работа в программе (от сервера не зависит, делается и проверяется заранее):**
- **Разделение данных клиентов.** Сейчас программа рассчитана на один магазин: одна база, один `config.ini`. Для общего сервера каждый клиент должен видеть только свои данные. Предложение для старта: отдельная база SQLite на клиента (`data/tenants/<id>/mp.sqlite`) + общая база учётных записей и подписок — код почти не меняется, изоляция надёжная, резервные копии по клиентам. PostgreSQL — позже, если упрёмся в производительность.
- Ключи WB/Ozon каждого клиента — в его настройках (сейчас в `config.ini` открытым текстом; на общем сервере — шифровать).
- **Регистрация и вход** (сейчас пользователей создаёт админ вручную), восстановление пароля.
- **Тарифы и подписка:** срок оплаты, предупреждение за несколько дней, после срока — только просмотр.
- **Мастер первого запуска:** ключи, проверка ключей (уже есть кнопка «Проверить»), счета, налоги, себестоимость.
- **Очередь загрузок:** один планировщик обходит всех клиентов (сейчас — задачи Windows / таймеры systemd на один магазин), лимиты API считаются на ключ клиента.
- **Приём оплаты** через сервис (ЮKassa, CloudPayments, Робокасса и т. п.) — у них же чеки.

**Сервер (покупается и настраивается, когда программа готова):**
- Хостинг **в России** — по 152-ФЗ персональные данные граждан РФ (телефоны пользователей и т. п.) должны храниться в базах на территории РФ. Подходят TimeWeb Cloud, Selectel, Yandex Cloud, VK Cloud. Обычного облачного сервера (VPS) хватает; для первых десятков клиентов — порядка 2–4 ядер, 4–8 ГБ памяти, диск с запасом (база одного магазина Mocheqi ~240 МБ).
- На сервере: программа как служба, nginx + HTTPS-сертификат, домен, резервное копирование баз, автообновление из GitHub (скрипты `server/` уже есть — дорабатываются под многих клиентов).
- Юридически: политика обработки персональных данных, уведомление в Роскомнадзор, договор-оферта с клиентами.

## 4. План по шагам

1. В mocheqi: развод имён от настроек (порт, cookie, задачи, ярлык, брандмауэр) — для Mocheqi без изменений.
2. В mocheqi: тумблер «Режим продукта» (выключен), каркас скрытых разделов.
3. Перенос особенностей Mocheqi в настройки (Google Таблица, МРЦ, магазины, название).
4. Мастер первого запуска для нового клиента.
5. Разделение данных по клиентам, регистрация, подписка, очередь загрузок — проверяется локально.
6. Выбор хостинга, домен, оплата, юридические документы, запуск.

Каждую правку проверять на копии базы Mocheqi с **выключенным** режимом продукта, прежде чем ставить на ПК.
